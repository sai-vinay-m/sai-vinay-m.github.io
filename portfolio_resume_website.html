Incident Walkthrough: Missing Curl Base Image

Context: During mid-sprint builds, multiple services suddenly stalled at the Docker deployment step. Engineering leads requested an urgent investigation under a 60-minute window.

Step 1: Container Log Inspection
Inspected container runtime logs for stratus/subscription-options-service and hpone-onbooks-dc. Confirmed Tomcat initialized properly on port 8080 (Started SubscriptionOptionsApplication in 7.55s).

Step 2: Isolation of Healthcheck Script
Identified exit code 127 returned by the container healthcheck ping:
/bin/sh: /usr/bin/curl: not found.

Step 3: Root Cause & Resolution Direction
Cross-checked with Harbor image update history (harbor.ext.hp.com/onecloud/java-service-base:latest). A recent slim-down had stripped curl without updating the healthcheck directives. Delivered detailed triage findings for team wiki.

Architecture Audit: Multi-Environment ARN Drift

Context: A 15-file PR was submitted updating Terragrunt and Runway configurations across environments (stg and pro).

The Catch: In environments/csc-hpone-sf-stg-pro/pro-subscription-options/global/service.hcl, the production tropos role ARN was set identically to staging: arn:aws:iam::126350429920:role/stratus-pro-subscription-options-service.

Impact: If deployed, production traffic would have attempted to authenticate using staging privileges, triggering authorization rejections under live workloads.

KMS Impact Assessment: Additionally verified that new ARN keys generated by tag 3.3.1 would not invalidate encryption keys in OBC and Subscription Control.
