Case 01 Walkthrough: Multi-Service Docker Healthcheck Triage

Context: Mid-sprint deployments across multiple enterprise subscription and domain controller microservices began failing abruptly at the container preparation stage. I volunteered to isolate the root cause under a 60-minute SLA window.

  • Runtime Verification (Hypothesis Disproved): Inspected container runtime logs and proved the Spring Boot applications initialized cleanly in ~7.55 seconds on Tomcat port 8080—ruling out application code regressions.
  • Pinpointing ExitCode 127: Correlated the container failure to the readiness probe (/bin/sh: /usr/bin/curl: not found) failing when pinging the local health endpoint.
  • Upstream Root Cause & Runbook: Traced the issue to an upstream hardening update of the shared enterprise Java base image that stripped curl. Documented the complete triage steps for the engineering wiki in under 45 minutes.
